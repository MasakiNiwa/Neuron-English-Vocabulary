## 学習の記憶モデルの更新（ts-fsrs 6・FSRS-7）の計画（2026-11-07）

復習日を決める部品 ts-fsrs の 6.0.0（Dependabot #134）は、新しい記憶モデル FSRS-7 と新しい計算エンジンを含む大きな変更で、
学習カードの保存形式も変わる。学習記録を失わないことを最優先に、段階を分けて進める。急ぎの不具合・脆弱性の修正ではない。

| 段階 | 内容 | 確かめること |
|---|---|---|
| 0 準備 | CI・デプロイの Node.js を 22 → 26（LTS）に上げる（ts-fsrs 6 が Node.js 24 以上を必要とする。26 は 24 より約 1 年長く保守される）——v0.130.0 で完了。残りは、更新前にバックアップを書き出す案内を出すこと | ビルド・テストが Node.js 26 で通る |
| 1 部品だけ更新（FSRS-6 のまま） | 計算は今と同じ FSRS-6 を明示して使い、ts-fsrs 6 の API に書き換える。カードの `elapsed_days` が廃止されるので、DB の版を上げて取り除き、バックアップの検証・復元は新旧どちらの形も受け付ける | 同じカード・同じ回答で次の復習日が今と同じになる（間隔のゆらぎ（fuzz）の乱数は変わるため、ゆらぎなしで比べる）。古いバックアップを復元できる |
| 2 FSRS-7 を選べるように（試行） | 設定に「新しい記憶モデル（FSRS-7）」を追加し、オンにすると、これまでの回答の記録（reviews: 回答日時・評価）から Reschedule.replay で記憶の状態を作り直す。予定の復習日・回数は保つ。いつでも FSRS-6 に戻せるよう、切り替え前の状態を残す | 記録が足りないカード（バックアップから取り込んだカードなど）の扱い。分析画面の「覚えている見込み」が極端に変わらない |
| 3 新しい機能を活かす | 何度も忘れる語（リーチ）を見つけて「苦手な語」として別に学べるようにする。評価ごとの目標記憶率、学習の段階（1分・10分）の見直し | 実際の使い心地。設定を増やしすぎない |
| 4 既定を FSRS-7 に | 2 の試行で問題がなければ、新しく始める人の既定を FSRS-7 にする | — |

- それまでの間、#134 は開いたままにし、Dependabot の新しい版も同じ段階で取り込む
- 回答の記録（reviews）は今も全件残しているので、段階 2 の作り直しに使える

## 2026-11-05 のコードレビュー・脆弱性分析（v0.105.0 時点）への対応

| ID | 内容 | 対応 |
|---|---|---|
| S01 | URL の質問（#/ai?q=…）が、送信の確認なしに AI へ送られる | URL の質問は入力欄への下書きにとどめる。単語ページのボタンなどアプリ内から開いたときだけ自動送信（メモリ上の目印で区別）。AI による「学習に追加」は追加前に確認、一度に 20 語まで |
