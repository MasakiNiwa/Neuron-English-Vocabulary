# 今後の取り組み予定

2026-11-03 に外部レビュー（v0.81.0 時点）を受けて整理した改善予定。
「間違ったつながりを教えない」「追加した語を迷わず学べる」「学習記録とバックアップを信頼できる」を、
機能追加や語数増加より優先する。

- 状態: ✅ 対応済み / 🔍 現行コードで確認済み（未対応） / 📝 未確認（着手時に再現から）
- 優先度: P1 = データの信頼性・誤学習・主要導線 / P2 = 日常利用での混乱・復帰・アクセシビリティ / P3 = 拡充・長期設計

## 対応済み

| ID | 内容 |

| — | ChatGPT / Gemini による語源監査（PR #85）のうち、元データからのフルビルドで確認できた修正を取り込み |

## PR 1: データを守る基盤（P1〜P2）

| ID | 状態 | 内容 | 方針 |

## PR 3: 誤学習を減らすコンテンツ修正（P1〜P2）

| ID | 状態 | 内容 | 方針 |
|---|---|---|---|
| B04 | 🔍 | 例文の is が I にリンクする（末尾 s を外す簡易処理のため） | 生成時に活用形→見出し語の索引を作り、曖昧なものはリンクしない |
| B06 | 🔍 | 4択で正解と同じ訳が誤答に入りうる（maybe／perhaps など） | 正解と同じ表示・同義語を除外し、候補不足でも止まらないようにする |
| C03 | 🔍 | 活用形の欄に古形・非標準形・別語義が混ざる（lie に laid、understand に understandest など） | 抽出時に form の tags を保持し、標準形を優先表示 |
| C04 | 🔍 | 多義語の発音が1つ（lead が「導く」なのに鉛の /lɛd/） | 品詞・意味ごとの発音を並べる |
| C05 | 📝 | 熟語の訳の優先順位（number one が「小」から始まる等）。熟語の手動訳・解説の整備率が低い | 上位の熟語から訳と用法ラベルを校閲 |
| C06 | 📝 | 熟語の例文が活用形（depends on 等）だと穴埋めに使えない | 生成時に例文中の該当箇所を確定して保存 |
| C08 | — | 07_note_parts_report の候補は誤り確定一覧ではない | 語基を介したつながり・異説を確認しながら少しずつ直す（自動一括修正はしない） |
| — | — | pre:in（否定）と pre:into（中へ）を使っている全語を意味別に監査 | |
